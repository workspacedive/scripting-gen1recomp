# Architecture

## Binding design

Suite 3.5.0 runs **real Gen1Recomp Lua code on LÖVE 11.5 WebAssembly in Scripting’s WKWebView**. It contains no Game Boy CPU/PPU emulator and no emulator fallback.

The product has three boundaries:

1. **Native Scripting shell** — full-screen four-tab TSX UI with explicit leading close actions, game/mod libraries, dependency/conflict health, persistent complete console diagnostics with four temporary export formats, a persistent streamed download manager, recovered settings, component registry, document pickers, bounded transactional self-contained ZIP/DEFLATE handling, opt-in update tools, and native save/mod-state/mod-option mirror.
2. **Serverless local-file transport** — documented `WebViewController.loadFile()` with metadata-only `launch.js`, bounded local chunk scripts, and one preallocated array per binary; no socket, listening port, HTTP server, or Scripting PRO API.
3. **Genuine game runtime** — the byte-exact immutable official Gen1Recomp v0.1.78 core, a separately versioned 312,056-byte revision-9 executable source layer, and the Davidobot/love.js compatibility build. The layer is `/game.love`; the unchanged core is transported separately as `/gen1recomp-core.love`, re-hashed inside LÖVE, and mounted behind the layer. No reconstructed patched core is executed or shipped.

The current official Scripting metadata marks `Thread`, core/async `FileManager`, `Data`, `Crypto`, and `WebViewController` as available without PRO. This project still excludes PRO-marked `Archive`, `HttpServer`, `BackgroundKeeper`, SQLite, Core Haptics, CloudSharedData, and Remote Push. There is no claim that work continues after iOS suspends or kills Scripting; journals/partials only recover on a later run.

The target-device 3.2.8 report established that the Mod settings editor opens and works, but also showed that Scripting did not reliably refresh a conditional `topBarLeading` item after switching the Mods tab from its list state into its editor state. Version 3.2.9 therefore made navigation escape content, not toolbar-only decoration: one stable toolbar `Button` changes its label/action, while a prominent in-content **Back** control and separate **Close** control render before the editor title. Version 3.3.0 retains those controls and addresses the next genuine 3.2.9 device trace: caught post-ready generic alerts no longer dismiss gameplay, downloads are persistent/resumable and visible, and PotatoVoxel’s dynamically generated settings normalize correctly.

## Why generated launch data is used

Ordinary `fetch`/`XMLHttpRequest` of binary resources from `file://` is not reliable in WKWebView. LÖVE Web also needs its WebAssembly binary and Emscripten package before Lua starts. Direct binary-file loading remains a future capability-gated experiment rather than a production dependency. The native host therefore retains local JavaScript injection; 3.5.0 preserves 3.4.0’s removal of the two monolithic fields and the full `Data.combine(parts)` copy.

`launch.js` now contains only exact package byte ranges, runtime options/capabilities, and transport metadata. Native serially slices each source `Data` into at most 1 MiB and writes deterministic `binary-wasm-NNNN.js` / `binary-package-NNNN.js` files. `binary-transport.js` validates local filenames, preallocates exactly one destination `Uint8Array` for each kind, requires exact kind/index/offset/decoded length, and copies each temporary `atob` result directly into its final offset. Each chunk script removes its current DOM node; `take(kind)` clears the transport reference. A read-only legacy whole-Base64 branch remains for an older launch envelope, but 3.5.0 native code cannot generate that envelope.

`runtime/index.html` takes the completed WASM array before love.js starts and supplies it as `Module.wasmBinary`. The copied `game.js` takes the package array and passes its `ArrayBuffer` into the existing Emscripten file packager without fetch. `WebViewController.loadFile(entry, runtimeDirectory)` grants read access only to that temporary runtime directory. The old packager still copies package bytes into the Wasm heap, so chunking reduces encoded-string/raw-decode overlap rather than claiming zero-copy startup.

The temporary directory path is fixed for consistent file-origin storage behavior. A small `runtime-recovery.json` journal is atomically committed before presentation. Clean close deletes the entire private runtime asynchronously and clears the marker; if iOS terminates first, the next launch detects either marker or directory and removes both before rebuilding. The journal contains session/state/time only—no ROM name, hash, or content. Generated chunks are never copied into the distributable project or long-term Documents storage.

The page installs its diagnostic/error bridge before any generated or runtime script. Emscripten’s generic blocking browser alert is replaced by the persistent trace and an in-player fatal panel before readiness. Davidobot’s customized LÖVE build emits the same generic alert when Lua `pcall` catches a C++ LÖVE exception, so an alert after the verified game-loaded marker is retained as a warning and does not close by itself. `Module.onExit`, `Module.onAbort`, uncaught `window.error`, unhandled rejection, explicit close, and the fatal-panel close button use distinct validated `closePlayer` reasons. Native defensively ignores only the ambiguous legacy `browser-alert-after-ready` reason, awaits documented `WebViewController.dismiss()` for terminal reasons, coalesces concurrent requests, and resets the guard after dismissal failure so a visible close path can retry. Successful dismissal returns to the still-present dashboard, then performs final sync/disposal/temporary-directory cleanup.

## Launch sequence

```text
User selects game
  -> recover/delete a prior interrupted temporary runtime and journal, if present
  -> asynchronously read and SHA-256-verify the separately stored execution layer, immutable core, love.js, and love.wasm
  -> asynchronously read the selected local user ROM and allowlisted save mirror
  -> select enabled mods only; asynchronously read each enabled packed mod, background-hash and parse its bounded central structure (or enumerate enabled compatible legacy directories)
  -> retain ordered Data parts and exact package byte ranges without a full combined copy
  -> atomically commit the private launch recovery marker
  -> write metadata-only launch.js and ordered <=1 MiB local chunk scripts with async FileManager I/O
  -> copy index.html, runtime.css, binary-transport.js, love.js, and package loader locally
  -> WebViewController.loadFile(index.html, runtime directory)
  -> binary-transport.js validates/decode-copies chunks into preallocated WASM/package arrays
  -> index.html takes Module.wasmBinary; game.js later takes package bytes
  -> game.js removes stale expanded and packed IDBFS mod trees from the prior launch
  -> game.js creates execution-layer /game.love, separate /gen1recomp-core.love, /web-rom-<edition>.gbc, saves, native-mod-packages, any legacy mods, native_mod_state.json, and native_mod_options.json without XHR
  -> official LÖVE boot loads the layer's conf.lua first
  -> the conf broker reads the separate core, verifies its exact size and SHA-256 again with love.data, mounts it in memory appended behind the layer, executes compat/core-conf.lua, and forces the writable save identity behind executable sources
  -> the layer's main broker rejects any compatibility module resolved from the writable save directory, then enters compat/core-main.lua
  -> layer-shadowed genuine Loader mounts validated archives lazily at mods/<id> through LÖVE/PhysFS
  -> genuine Loader discovers the enabled payload set present in its ordinary filesystem view, applies the complete native state mirror, normalizes live schemas, migrates known values, then applies profile/native precedence
  -> restored save files are created under their original IDBFS paths
  -> layered main compatibility selects that ROM and its matching version/cache prefix
  -> genuine RomImporter validates SHA-1 and extracts ROM-derived cache
  -> Gen1Recomp boots the selected game
```

The package loader does not use Emscripten’s `EM_PRELOAD_CACHE`; otherwise the combined package could persist a duplicate of the user ROM and mod library in package IndexedDB. Gen1Recomp’s own derived cache and working saves can remain in WebKit IDBFS. The native save mirror is the host-controlled persistence layer and is restored independently of WebKit cache availability.

## Browser-compatibility patches

`runtime/gen1recomp-core-0.1.78.love` is the byte-exact official v0.1.78 package (4,418,896 bytes; SHA-256 `4dfd6e78808024eda0cce8b9fa5434a5846d1aa327912f7a1ce3c888e416c4fe`) and contains none of the suite markers. It is never edited, rebuilt, or used as the `/game.love` source. `runtime/gen1recomp-layer-2.1.0.love` is a separate 312,056-byte source archive (SHA-256 `d0f9fbc9af9e2d11a26ad1a3c5639205c8d32f62941d7fc3847249d69314ca71`) with only 14 files: two boot brokers, two compatibility copies of upstream `main.lua`/`conf.lua`, eight shadow modules (including the layer-owned updater policy), `bit.lua`, and its internal activation/per-file-integrity manifest.

This is the Chrome-inspired component boundary in concrete form, not just a descriptive manifest. Native code independently verifies both components before transport. Official LÖVE 11.5 boot selects the layer as its source and therefore loads layer `conf.lua` before modules or `main.lua`. That broker reads the separately injected core from host-owned MEMFS, checks 4,418,896 bytes and SHA-256 with `love.data`, creates a `FileData`, and mounts the core at `/` with `appendToPath=true`. The layer source remains first. Its wrapped `love.conf` sets `appendidentity=true`, so writable save files cannot shadow layer/core code. The layer's `main.lua` broker explicitly rejects any critical module whose real directory is the writable save directory before loading `compat/core-main.lua`. Absence, size mismatch, digest mismatch, mount failure, or precedence failure stops before core execution with a stable `[gen1-layer:*]` reason.

`config/compatibility-pack.json` schema 2 separately versions the layer as 2.1.0, pins the exact compatible core, declares revision 9, activation/rollback policy, required capabilities, and every effective target. `tools/test_compatibility_pack.py` proves all 453 upstream files remain byte-identical, the 14-file layer has no undeclared core content, and exactly eleven effective target paths differ. `tools/test_execution_layer.mjs` proves deterministic layer generation and broker contracts. A fresh Chromium 140 direct-file run additionally proved the real boot order: both `[gen1-layer] mounted…` and `precedence verified; entering immutable core` appeared, the title became `gen1recomp v0.1.78`, the canvas resized to 390×844, native telemetry ran, and no page error or network request occurred. Separate runs proved a corrupt core fails at `core-digest`, an absent core fails at `core-absent`, and a malicious save-directory `src/mods/Loader.lua` cannot execute. A fourth containment fixture injected a malicious writable `src/update/Boot.lua`, pending marker, and executable updater archive: no malicious marker executed, the layer-owned updater removed the pending/archive bytes, and the immutable core still entered normally.

`tools/build_web_love.py` accepts only that verified official package and deterministically invokes the same TypeScript layer builder used for component installs. It emits no patched-core archive. The layer applies twenty-two narrow Web-host changes around the mounted core:

1. **Preloaded ROM handoff** — find `web-rom-<edition>.gbc`, select the same edition for cache readiness, and pass the path to `RomImporter:startPath`. This avoids re-extracting Blue/Yellow/Gold merely because Red’s cache is absent.
2. **Pure-Lua bit module** — add `bit.lua` and publish global `bit`, because compatibility love.js uses standard Lua 5.1 without LuaJIT BitOp.
3. **Missing-cache guard** — call `love.filesystem.getInfo` before a missing cache read. The compatibility runtime otherwise logs the miss but does not return to Lua.
4. **Web touch controls** — treat LÖVE’s `Web` OS as touch-overlay capable, reusing Gen1Recomp’s own control implementation and art.
5. **Queueable audio compatibility** — do not call unsupported `setLooping` on chip-music queueable sources; ChipSynth already implements loops.
6. **Narrow viewport floor** — lower the web-only minimum window width/height to 320 so iPhone portrait controls stay on-screen.
7. **Standard-Lua mod source compatibility** — map string `load` to Lua 5.1 `loadstring`, strip a UTF-8 BOM, and normalize LuaJIT `LL`/`ULL` hexadecimal suffixes. This lets API-2 packages compile without LuaJIT while dormant FFI/VR modules remain dormant.
8. **Native mod profile bridge** — read `native_mod_state.json` before discovery and write it whenever the genuine in-game manager changes an enable flag.
9. **Optional mod-file guard** — probe `mod:read` paths before a missing compatibility-PhysFS read that otherwise does not return to Lua.
10. **Depth-format preflight** — reject readable depth canvas formats that LÖVE itself reports unsupported before entering the compatibility native binding, allowing visual mods to use their internal depth-buffer fallback rather than stall on a black frame.
11. **Native mod-option bridge** — read schema-2 `native_mod_options.json`; validate bounded primitive state; clear known keys; apply unsuppressed catalog profile values; apply explicit values last; then normalize `loader.optionSchemas` only after genuine sandboxed discovery. RFC-0008 `[label, value]` tuples and common object choices preserve a legitimate boolean `false`; `maxLen` and bounded `maxLength` are accepted, and a malformed row is skipped without erasing valid siblings. Exact Gen1Recomp fallback defaults are toggle `false`, number `0`, first choice, empty text, and text max length `7`. Existing values migrate once when their schema/version becomes known, and every schema/value write-back is bounded and atomic.
12. **Packed-mod mount** — on Web only, enumerate integrity-checked archives under `native-mod-packages`, validate their ID-shaped filenames, and mount each lazily at the ordinary `mods/<id>` path through LÖVE/PhysFS before genuine discovery.
13. **First-transform stamp guard** — probe the optional `save/mod-derived/<id>/.stamp` before reading it. Compatibility PhysFS otherwise logs a missing file but may never return to Lua; this was the exact Kanto Ascendant v6.0.11 startup stall.
14. **Cooperative Web transforms** — keep desktop/native LÖVE behavior synchronous, but on no-pthreads Web queue first-run ROM-derived art work after boot and yield after each committed image. Genuine gameplay starts first, a non-blocking badge reports progress, errors remain attributed, and a successful stamp makes later boots skip the work.
15. **Strict terminal-continue compatibility** — before Web compilation only, recognize a conditional `goto` whose target label is the final statement of the containing `for`/`while` loop. Regions with nested loops, `repeat`, an existing `break`, non-terminal labels, or arbitrary goto shapes are not transformed. A recognized loop is represented with an equivalent inner `repeat … until true`; the installed mod archive stays unchanged.
16. **Wilds ImageData encode preflight** — wrap standard-Lua `loadstring` as well as `load`, because Wilds 1.12.2 compiles `lib/spawn_render.lua` itself from `mod:read`. At that exact module path and exact source anchor only, check `ImageData:getFormat()` before its optional PNG bake. LÖVE 11.5’s PNG handler accepts `rgba8`/`rgba16`; a valid iOS/WebGL `rgba4` readback returns through Wilds’ existing `nil` fallback instead of entering a compatibility native exception that escapes Lua `pcall`. No installed archive is rewritten.
17. **PotatoVoxel v1.4.4 retry retirement** — only at the exact `potato_voxel` module paths and unique publisher source blocks, convert `SpriteBillboards.buildShadowBlob`’s Lua-table vertex map from invalid zero-based indices to one-based indices, retain a complete first `OverworldBattle` traceback and stop updating a session after `session.broken`, and latch the actor-decal pass off after its first detailed failure. Data-form maps stay zero-based, `Voxel3D.pushQuad` is untouched, nonmatching sources remain unchanged, and the installed archive is never rewritten.
18. **First-failure Lua diagnostics** — print a `[native-lua-error]` traceback before the upstream error handler performs filesystem work, then probe optional `lua-error.log` with `getInfo(..., "file")` before reading prior history. This preserves the originating exception and avoids constructing the secondary missing-file `love::Exception` that Davidobot’s Emscripten customization otherwise turns into a generic initialization alert. Existing append, redaction, rotation, and LÖVE error-screen behavior remain in place.
19. **Verified option persistence observation** — after genuine `SaveData.saveOptions` successfully writes `options.lua`, normalize the known live option rows and atomically refresh `native_mod_options.json`. This captures Gen1Recomp’s START → MODS editor and compatible custom menus without replacing their persistence path or swallowing their errors.
20. **Measured Lua/graphics telemetry** — Web-only state reuses one `love.graphics.getStats` table and prints Lua KiB, draw calls, batched calls, canvas switches, texture bytes, images, canvases, and fonts every ten seconds. Unsupported fields become `na`; no cache/tuning decision is made from an unavailable metric.
21. **Low-memory response** — the existing Web `love.lowmemory` path retains upstream resume behavior, then performs one explicit emergency full collection and reports post-collection Lua KiB. Normal frames do not force full collections or apply speculative Lua-5.1 GC tuning.
22. **Host-owned updater boundary** — the layer shadows upstream `src/update/Boot.lua`. Its pure version selector remains API-compatible, but archive probing, root prepend-mounting, `loadstring`, `main.lua` chainloading, and writable callback replacement are absent. `Boot.run` probes before optional reads, removes only strictly named stale payloads/pending markers, and always continues into the already verified core. Engine and layer updates therefore pass through the native hash/manifest/transaction boundary instead of save-directory executable content.

The bundled executable layer is 312,056 bytes / 14 files at SHA-256 `d0f9fbc9af9e2d11a26ad1a3c5639205c8d32f62941d7fc3847249d69314ca71`. Layer generation is byte-deterministic. A full materialized archive may still be produced transiently by regression tooling to compare the effective view, but it is not a runtime component, is not referenced by the catalog, and is not packaged.

`runtime/love.js` has one host patch: `Module.FS = FS`. This exposes the existing Emscripten filesystem object to the local shell for explicit `syncfs`, save snapshot, and restore operations. It adds no network behavior.

## Save model

LÖVE mounts IDBFS at `/home/web_user/love`. Gen1Recomp identity `pokemon-love2d` therefore stores data at:

```text
/home/web_user/love/pokemon-love2d/
```

The shell snapshots only an allowlisted subset:

- `options.lua`, `.bak`, `.tmp`;
- `native_mod_state.json` (booleans only, reconciled with `mods.json`);
- `native_mod_options.json` (bounded schema-2 primitive values, known-key sets, reset suppression, captured schemas, discovery flags, active profile, and catalog-managed-key metadata);
- exact upstream diagnostics files `lua-error.log` and `lua-error.log.1`, so an originating Lua traceback survives player dismissal/relaunch;
- legacy `save.lua`, `save_blue.lua`, `save_yellow.lua`, `save_gold.lua` and backups/staging files;
- `saves/red/**`, `saves/blue/**`, `saves/yellow/**`, `saves/gold/**`.

ROM-derived generated cache files are not copied through the native message bridge. Snapshot limits are 128 files, 8 MiB per file, and 24 MiB total. Paths reject absolute components, `..`, unknown roots, and unsafe characters.

Native writes use a staging directory followed by replacement of `Gen1Recomp Saves`, preventing a partially decoded message from replacing the last good mirror. The latest save mirror is appended to the next injected package under the original IDBFS paths. Mod files come from the separate native `Mods/<id>` library; only their small active profile crosses the save bridge. An explicit normal-close `syncfs` and snapshot is attempted before disposal; periodic and lifecycle snapshots avoid overlapping `syncfs` operations. Before a periodic pass reads any save bytes, the page compares a stable sorted inventory of allowed path, size, and modification time against the last accepted snapshot. An unchanged inventory emits one diagnostic and skips file reads, Base64 allocation, and the native bridge. Final synchronized snapshots deliberately bypass that suppression and submit every allowlisted file. The periodic native mirror is selectable at 10, 15, 30, or 60 seconds (15 seconds by default). Runtime sampling reports bounded ten-second frame aggregates plus diagnostic-only Wasm heap, optional JS heap, Lua heap, and reusable LÖVE graphics statistics. The Settings state still persists only the latest valid FPS/slow/worst trio; complete technical fields use the existing bounded local JSONL journal.

## Mod model

`mods.json` schema 1 is metadata and the active profile. New installs live as `Documents/Gen1Recomp Native Suite/Mods/<id>/package.zip` plus an exact package SHA-256 in metadata; expanded directories created by earlier releases remain readable. Loading sanitizes every field and can recover from `mods.backup.json`.

An imported ZIP is treated as untrusted executable content. `modules/zip.ts` parses EOCD, central records, matching local records, methods, flags, offsets, and Unix/DOS types without calling any Scripting archive API. Unsafe/absolute/traversing or case-colliding paths, overlapping records, symlinks, encryption, ZIP64/multi-disk input, unknown API-2 permissions, ambiguous package manifests, and ROM/save/state/IPA extensions are rejected. Package-manifest discovery considers exactly `manifest.json` at archive root or `<wrapper>/manifest.json`; this matches ordinary release packaging while allowing deeper asset trees to contain their own unrelated manifests.

`modules/mod-limits.ts` keeps independent bounds instead of reusing one file-count ceiling for every purpose: 64 MiB compressed ZIP, 40,000 ZIP entries, 32,768 regular files per archive, 49,152 files across the installed runtime set, 128 MiB extracted/installed bytes, 32 MiB per file, and 256 KiB for the package manifest. The archive is read through asynchronous `FileManager.readAsData`. `readLocalZip` runs off-main; scan stages are capped at 256 entries; CRC/DEFLATE verification stages are capped at 16 entries and 8 MiB declared output (one legal 32 MiB entry can form a one-entry stage). `onProgress` is called only after `await` returns to the initiating thread, never from the worker. If `Thread` is unavailable, the exact same code runs through a correctness fallback on the caller and diagnostics expose that missing capability.

After verification, `createRepackedZipFromArchive` runs off-main, strips an optional wrapper, discards only known platform metadata, and copies each already-verified compressed range directly from the source archive into one normalized output—without retaining a separate sliced compressed array per file. The package is written through asynchronous `FileManager.writeAsData` into a random staging directory. Manifest/exact-case entry, package hash, and metadata then commit transactionally. At launch package reads are asynchronous while hash/central parsing use the same bounded worker helper; one compressed file crosses the native package boundary and PhysFS expands assets lazily. Save export still uses the deterministic stored-ZIP writer rather than the PRO-only host archive API.

Only enabled mod payloads are injected or mounted for a launch. This removes disabled archives/directories from the temporary package, browser filesystem work, integrity enumeration, and Wasm-side discovery cost. `native_mod_state.json` still mirrors the complete installed library—including disabled IDs—so the native menu remains authoritative and a mod re-enabled there is selected on the next launch without reinstalling. Genuine **START → MODS** can change state for the enabled set loaded into that session; the patched loader writes that state after in-game changes, and normal-close/periodic snapshots reconcile it back to native Documents.

`modules/mod-validation.ts` accepts an optional manifest `options_schema` path only after normal path normalization and bounded UTF-8 validation. `modules/mod-options.ts` parses that file as data using a custom tokenizer/recursive literal-table parser: it permits Lua comments and literal tables but no identifiers as values, operators, calls, functions, local declarations, metatables, or trailing statements. Normalization then enforces 128 rows per mod, 128 choices per row, ID/key/text bounds, unique keys, finite numbers, valid defaults, and a bounded serialized state. Failure declines early native discovery but does not execute the file or unnecessarily reject an otherwise valid mod.

Dynamic schemas remain inside genuine Gen1Recomp. After ordinary sandboxed mod initialization and upstream lazy schema loading, the revision-9 execution-layer module normalizes `loader.optionSchemas`, applies exact missing-default semantics, and atomically writes the mirror. Native state stores schemas by mod ID and installed version, so update reconciliation drops a stale schema while preserving safe explicit primitive values until the new version is discovered. Uninstall removes that mod’s schema/discovery metadata but deliberately preserves shared option values, matching upstream’s persistent `options.lua` behavior and supporting reinstall.

The canonical runtime values remain `options.modOptions[modId][key]`. Boot precedence is: clear known managed/schema keys, apply unsuppressed profile values, then apply explicit native/in-game values. A per-mod reset deletes explicit values and marks that mod’s profile seeding suppressed, so the current version’s declared defaults win; deliberately choosing a profile clears suppression and explicit values only for that profile’s managed keys. SaveData write observation and periodic/final snapshot collection return later in-game changes. Atomic native commits use `.tmp` plus backup recovery, and runtime cache invalidation after each snapshot prevents stale host state from overwriting a newer in-game write.

Update checks are opt-in, either as a direct action or through the Settings schedule. Checks never install automatically. The direct URL action accepts only a strict GitHub repository/latest/exact-tag release form and converts it to the corresponding repository API endpoint. A repository must normalize to `owner/repo`; metadata and asset URLs must remain under that repository’s GitHub release paths; ZIP size is bounded; and download/install requires GitHub’s SHA-256 digest plus user confirmation. The external Dramatic Shape shortcut uses `scottcandy34/DramaticShapeVoxelMod-latest`. No third-party mod is bundled or redistributed.

## Persistent download manager

`modules/downloads.ts` is the shared asset transport for engine components, GitHub mods, and official IPA downloads. Release metadata supplies a bounded expected size and mandatory SHA-256 before a job can exist. Response `dataStream` yields native `Data` chunks that are appended directly to a `.part` file with `FileManager.appendDataSync`; UI observers receive throttled byte counts, speed, attempt, state, and resume support for a determinate linear progress card on Mods and Settings.

The queue persists metadata under `Download Manager/downloads.json` beside `Partials/*.part`. Every commit writes the fixed `downloads.tmp.json`, rolls the prior primary to fixed `downloads.backup.json`, installs the new primary, and only then removes the backup. If the primary is missing, corrupt, or interrupted between renames, startup tries the fixed backup; recovered records are sanitized and rewritten as a new primary. Fixed names avoid orphaned random transaction files, and a backup that is the only recoverable queue is preserved until the replacement primary is installed. On a later suite process, any interrupted `queued`/`downloading`/`retrying`/`verifying` state becomes paused and its byte count is reconciled from `statSync`, not trusted from JSON.

A retry sends `Range: bytes=<exact-file-size>-` and `If-Range` with a saved ETag or Last-Modified value. Only `206` with a syntactically valid matching `Content-Range` may append. A resumed `200` means Range was ignored or the validator changed, so the partial is removed before the full body is written. `416`, malformed/mismatched ranges, inconsistent totals, excess bytes, and malformed chunks cannot promote data.

Transient transport, timeout, `408`, `425`, `429`, and 5xx failures retry at most six attempts with bounded exponential or `Retry-After` delay. Pause/cancel uses documented `AbortController`; pause retains the partial, cancel removes it. After exact size and SHA-256 pass, the caller receives bounded `Data` and performs its existing transactional patch/prepare/install. The manager entry is discarded only after handoff/preparation succeeds. There is no claim of background continuation after iOS terminates Scripting; persistence enables the next attempt to resume.

## Native mod health and diagnostics

The Mods tab derives advisory health from installed metadata without changing Gen1Recomp behavior. Dependency and conflict declarations may use `id` or `id@<range>`; the shell normalizes the identifier and reports missing dependencies, dependencies present but disabled, and declared conflicts whose other mod is enabled. These checks are preflight guidance, not a second mod resolver. Gen1Recomp remains authoritative at runtime.

Gen1Recomp’s `LOAD REPORT` is intentionally preserved. It reconciles the mod set stored in a save with the set active now, so “no longer active” or “newly active” after install, disable, removal, or update can be a legitimate informational safety report. Native help explains that distinction and does not suppress or auto-accept upstream migration warnings.

`modules/diagnostics.ts` maintains an append-only JSONL journal under `Documents/Gen1Recomp Native Suite/Diagnostics`. Native launch preparation, component verification, request policy, bridge registration, save commits, final sync, cleanup, dashboard failures, and complete error stacks are recorded. A bootstrap script runs before `launch.js`, `game.js`, and love.js; it wraps browser console methods and captures `window.error`, unhandled promise rejections, Emscripten abort/exit, browser alerts, WebGL context events, package metadata/decoding/injection, LÖVE output, and player lifecycle. Browser records queue behind one Promise chain and cross the native bridge as envelopes of at most 48 entries or after 40 ms; fatal events force a handoff. Native validates at most 128 entries per envelope, serializes accepted records in arrival order, and appends approximately 64 KiB / 75 ms batches through the documented asynchronous `FileManager` operation. If that append fails, the entire intact batch receives one synchronous fallback—never one fallback per line. Exports, clear, session end, and terminal cleanup await a durability flush. A `[native-lua-error]` line is additionally promoted to explicit runtime-error status and schedules an immediate snapshot; because the patched engine prints it before calling `SwitchDiagnostics.logLuaError`, the complete TXT/JSON/JSONL/CSV journal retains the originating traceback even if later error persistence fails. Web messages larger than 12,000 characters are retained as numbered records rather than silently sliced. Native accepts only bounded token/date/sequence/level/chunk metadata, and export readers revalidate the complete stored schema; invalid bridge records are rejected and malformed disk lines remain explicit rather than destabilizing an export.

Rotation is evaluated only before a new session: once the active journal reaches 8 MiB, it becomes the single previous journal and the new session starts in a fresh file. The active failing session is never truncated or rotated midway. If a crash left a smaller active file with an unterminated tail, session startup adds only a newline boundary: the interrupted bytes remain exportable as an explicit malformed record while all new JSONL records remain independently parseable. Settings reports entry/session/error counts and a bounded latest-error preview, offers confirmed clearing, and exports complete readable TXT, structured JSON, raw JSONL, or RFC-style quoted CSV through `DocumentInteraction.optionsMenu`. Each export is written to the temporary directory and removed after the system menu returns.

Suite-generated context excludes ROM bytes, save contents, original ROM filenames, ROM hashes, and cover data. However, preserving third-party/engine console output means a mod can itself print technical paths or gameplay state. Logs therefore remain local until explicit export and the UI tells the user to inspect them before sharing. No log is uploaded automatically.

## Settings and component-update model

`config/catalog.json` is the data boundary for the bundled engine, the coupled love.js/WASM runtime, featured-mod sources, and primitive-only Balanced/Efficient presets. `modules/config.ts` rejects malformed repositories, versions, commits, hashes, limits, IDs, and preset values before use. `modules/settings.ts` keeps schema-1 preferences with backup recovery and validates profile, update interval, save interval, and telemetry bounds.

The active engine/layer pair and Web runtime are optional local overrides under `Documents/Gen1Recomp Native Suite/Runtime Components`; bundled files remain immutable rollback assets. Before every launch, async reads plus background hashes reverify the separately selected layer, retained upstream core, JavaScript, and WASM against pinned catalog/state values. Current engine state carries execution-layer revision 9 and an exact `sourceFile`. A valid revision-8 installed pair is migrated before asynchronous activation: the retained core is reverified, revision-9 source is generated locally, old layer/state are backed up, new bytes and state commit, and post-commit activation is reverified. Failure restores exact old layer/state; because revision 8 cannot satisfy the current runtime contract, that launch selects the complete bundled revision-9 pair and reports `failed-bundled-fallback`. Materialized/revision-7 and older state remains ignored non-destructively. If an installed layer/core file is absent or corrupt, neither partially activates; selection falls back to the bundled verified pair. This prevents a hash-valid but capability-incomplete preserved engine or writable save file from bypassing packed mods, alert policy, diagnostics, dynamic options, chunk transport assumptions, or measured telemetry.

- **Engine/core:** the Update Center accepts one repository-bound latest-release `.love` asset within the catalog limit and only when GitHub publishes a SHA-256 digest. Versions must increase monotonically. After exact size/hash verification, `Thread.runInBackground` builds a new small layer for that exact core using guarded anchors. The downloaded upstream file remains byte-exact as `gen1recomp-core-active.love`; the executable source is separate as `gen1recomp-layer-active.love`. Both have staging and backup files, state commits only after both renames, and failure restores both. A future source change that no longer matches every guarded anchor fails closed.
- **Execution layer:** layer version 2.1.0 is independent of core version 0.1.78. **Import execution-layer update** accepts a user-selected source-only `.love` without rebuilding or replacing the core. It requires a strictly newer version, revision 9, suite minimum, exact selected-core version/SHA-256/byte count, deterministic-build marker, safe unique paths, the complete protected target set, and SHA-256/size records for every executable file. It stages, backs up, commits state, re-reads/re-hashes the activated archive, and rolls back on any failure. Corruption or core mismatch cannot partially activate; the verified generated/bundled layer remains usable. Because Scripting exposes hashes/HMAC/AES but no asymmetric signature-verification primitive and this release has no controlled publisher feed, local import is explicitly a trust action—not a claim equivalent to Chrome CRX publisher proof. A future network feed must add independently verifiable publisher signatures before automatic installation.
- **Web runtime:** JavaScript and WASM are never updated independently. A user may import one bounded ZIP containing schema-1 `runtime-manifest.json`, `love.js`, and `love.wasm`. Declared hashes, a 40-hex source commit, WASM magic/version, compatibility filesystem anchor, and absence of pthread/`SharedArrayBuffer` markers are verified before both files are staged. Existing JS and WASM are backed up separately; component state is committed only after both replacements succeed, and any failure restores both files and prior state.
- **Source awareness:** the suite may check the pinned runtime repository branch commit after opt-in, but a changed commit is not called an installable binary update. There is no established trustworthy drop-in binary feed for the patched no-pthreads pair.
- **Mods:** every installed mod with a normalized GitHub source can be checked together. “Update all” still verifies each repository-bound asset digest and re-validates every manifest/archive before transactional replacement.

Automatic checks use the user-selected 6/12/24/72-hour schedule and only run when the toggle is enabled. They update status metadata only; installation always requires a separate user action.

## Library model

`library.json` schema 2 stores metadata only. ROM bytes remain separate files. Parsing validates identifiers, SHA-1 syntax, bounded strings, known filename forms, support values, and custom-cover names. A rolling backup is retained.

Schema 1 migrates without deleting data. The old `showPlayerNotice` setting maps to `showRuntimeNotice`. Unsupported records from the removed emulator architecture remain visible for export/deletion but are not launchable.

## Lifecycle and cleanup

The root page is finite and explicitly presented with `modalPresentationStyle: "fullScreen"`. Every root tab exposes the same upper-left `xmark` dismissal action through `topBarLeading`. The Mod settings subview adds an in-content leading **Back** action and a separate **Close** action while retaining a toolbar back fallback. `Navigation.present` is awaited and `Script.exit()` follows dismissal.

Each player launch owns one temporary runtime directory, one `WebViewController`, and one small session-owned recovery journal. Preparation first calls `recoverInterruptedRuntime`, then atomically renames `.tmp` journal data into `runtime-recovery.json`. Cleanup is in `finally`: dispose the controller, asynchronously remove the ROM/chunk-bearing directory, and clear only the matching session marker. A stale/malformed marker is removed fail-closed by recovery; a marker owned by another live session is not cleared by the wrong session.

## Network boundary

The runtime CSP uses `connect-src 'none'`. Its WebView request policy permits only `file:`, `blob:`, `data:`, and `about:blank`, rejecting HTTP and HTTPS. The package loader contains no `fetch`, `XMLHttpRequest`, socket, or server code. External network functions live in `modules/releases.ts`, `modules/mods.ts`, `modules/components.ts`, and the shared `modules/downloads.ts` transport. They run only after a direct action or the persisted Automatic update checks opt-in. Checks are HTTPS metadata reads; installs remain separate and confirmation-gated. Engine/mod/IPA downloads are restricted to selected catalog, official, or manifest GitHub release URLs and require published digests.

## Known boundaries

- WebKit file-origin IndexedDB persistence was proven in direct `file://` Chromium tests but remains a device-qualification item in Scripting/WKWebView. The native save mirror does not depend on derived-cache persistence.
- Final IDBFS flush on abrupt iOS termination is not guaranteed; periodic native snapshots reduce loss but do not replace real-device qualification.
- The no-pthreads love.js compatibility runtime avoids cross-origin-isolation requirements, but its upstream README warns that audio can be imperfect.
- Chunking bounds each temporary Base64/raw decode to 1 MiB and eliminates the full combined native package plus long-lived whole-payload encoded fields. The preallocated package array still overlaps the Emscripten heap copy during the old packager handoff; real WebKit peak memory remains a target-device measurement, not an automated claim.
- Background ZIP/DEFLATE/repack and async I/O are documented free-tier paths and pass host-shim behavior tests. Thread data-transfer costs, progress rendering, cancellation expectations, and 10,000+ file memory/thermal behavior still require free-tier target-device qualification. Individual GPU-heavy visual mods do too. The supplied genuine 3.4.0 iPhone 16 Pro Max / iOS 26.6 trace proves PotatoVoxel 1.4.4 failure loops correlate with severe frame-time and memory degradation; it does not prove a single retained-Lua cause. Revision 9’s exact official-archive rewrites, enabled-only packaging, diagnostic batching, unchanged-save suppression, and revision-8 migration pass automated source/PUC-Lua/host-shim tests, but their real frame-time, memory, battle-start, walking, and migration effects require the named 3.5.0 device matrix. Arbitrary Lua mod code cannot be proven safe by manifest/archive validation.
- Scripting fetch is not a native background-transfer daemon. Partial bytes persist for a later attempt, but iOS may suspend/terminate the script and no completion is promised while the suite is not running.
- Gold remains an upstream beta/incomplete target.
